# Dockerez

[![npm version](https://img.shields.io/npm/v/dockerez.svg)](https://www.npmjs.com/package/dockerez)

Automatically detect supported projects and generate Docker configuration with minimal setup. 🐋

Dockerez scans a project directory, detects supported frameworks and databases, and generates Dockerfiles, `.dockerignore` files, Docker Compose configurations, and environment templates.

## Features

*  Recursive project detection
*  Automatic Dockerfile generation
*  Docker Compose generation
*  Database service detection
*  Persistent database volumes
*  Database healthchecks
*  Automatic service dependencies
*  `.env.example` generation
*  Docker configuration cleanup
*  Docker environment diagnostics
*  `--force` overwrite support
*  `--no-compose` mode for Dockerfile-only workflows
*  npm, Yarn and pnpm detection for Node.js projects
*  FastAPI detection for Python projects

## Installation

### Install from npm

```bash
npm install -g dockerez
```

### Verify installation

```bash
dockerez --version
```

## Quick Start

Navigate to the root directory of your project:

```bash
cd my-project
```

Analyze the project:

```bash
dockerez init
```

Generate Docker configuration:

```bash
dockerez generate
```

Dockerez will scan the directory and generate the appropriate Docker configuration based on the detected technologies.

## Commands

### `dockerez init`

Analyzes the current directory and reports detected projects and technologies.

```bash
dockerez init
```

Use this to inspect what Dockerez detects before generating Docker configuration.

---

### `dockerez generate`

Generates Docker configuration for detected projects.

```bash
dockerez generate
```

Depending on the detected project, Dockerez can generate:

```text
Dockerfile
.dockerignore
docker-compose.yml
.env.example
```

Existing files are protected by default.

If a generated file already exists, Dockerez will skip it and display a warning.

---

### `dockerez generate --force`

Forces dockerez to overwrite existing Docker configuration files.

```bash
dockerez generate --force
```

Use this when you want to regenerate the configuration after changing the project structure or detected technologies.

---

### `dockerez generate --no-compose`

Generates Dockerfiles and `.dockerignore` files without generating Docker Compose configuration.

```bash
dockerez generate --no-compose
```

This is useful when you only want containerization for individual projects and do not need a multi-container setup.

For example:

```text
my-project/
├── Dockerfile
└── .dockerignore
```

No `docker-compose.yml` or `.env.example` is generated by this mode.

You can also combine it with `--force`:

```bash
dockerez generate --force --no-compose
```

---

### `dockerez clean`

Removes Docker-related configuration files from the current project.

```bash
dockerez clean
```

Dockerez will first show the files it found and ask for confirmation.

The command can remove:

```text
Dockerfile
Dockerfile.dev
Dockerfile.prod
docker-compose.yml
docker-compose.yaml
.dockerignore
.env.example
```

This command can remove Docker configuration regardless of whether dockerez originally created the files.

---

### `dockerez clean --force`

Removes detected Docker configuration files without asking for confirmation.

```bash
dockerez clean --force
```

Use this carefully because existing Docker configuration files will be deleted.

---

### `dockerez doctor`

Checks the local development environment for the tools dockerez relies on.

```bash
dockerez doctor
```

The diagnostic checks include:

* Node.js
* npm
* Docker
* Docker Compose
* Current project
* Common Docker configuration files

Example:

```text
🩺 dockerez Doctor
================

✓ Node.js: v22.x.x
✓ npm: 10.x.x
✓ Docker: Docker version ...
✓ Docker Compose: Docker Compose version ...

Project:
  C:\Projects\my-project

✓ package.json: found
✓ Dockerfile: found
✓ docker-compose.yml: found

✅ Doctor check complete.
```

---

### `dockerez --help`

Displays available commands and options.

```bash
dockerez --help
```

Individual commands also provide help:

```bash
dockerez generate --help
dockerez clean --help
```

---

### `dockerez --version`

Displays the installed dockerez version.

```bash
Dockerez --version
```

## Supported Technologies

Dockerez currently supports the following project types.

| Technology | Detection | Dockerfile | Compose |
| ---------- | --------: | ---------: | ------: |
| Vite       |         ✅ |          ✅ |       ✅ |
| React      |         ✅ |          — |       — |
| Express    |         ✅ |          ✅ |       ✅ |
| Next.js    |         ✅ |          ✅ |       ✅ |
| FastAPI    |         ✅ |          ✅ |       ✅ |
| PostgreSQL |         ✅ |          — |       ✅ |
| MongoDB    |         ✅ |          — |       ✅ |
| Redis      |         ✅ |          — |       ✅ |

React is detected as a frontend technology, while Vite is used as the Docker build strategy for Vite-based frontend applications.

## Example Project

A project containing:

```text
my-project/
├── client/
│   ├── package.json
│   └── src/
│
└── server/
    ├── package.json
    └── src/
```

where the client uses Vite/React and the server uses Express/PostgreSQL can be detected automatically.

Running:

```bash
dockerez generate
```

can produce:

```text
my-project/
├── client/
│   ├── Dockerfile
│   └── .dockerignore
│
├── server/
│   ├── Dockerfile
│   └── .dockerignore
│
├── docker-compose.yml
└── .env.example
```

## Docker Compose

For multi-service applications, Dockerez can generate a Compose configuration containing the detected application and database services.

For example:

```yaml
services:
  client:
    build:
      context: ./client
    ports:
      - "5173:80"

  server:
    build:
      context: ./server
    ports:
      - "5000:5000"

  postgres:
    image: postgres:17
    ports:
      - "5432:5432"
```

Database services can include:

* Persistent volumes
* Healthchecks
* Environment variables
* Application dependencies
* Internal Docker service names

### Service networking

Containers communicate with each other using Docker Compose service names.

For example, PostgreSQL is reachable from another container using:

```text
postgres:5432
```

rather than:

```text
localhost:5432
```

Applications should therefore use environment variables such as:

```text
DATABASE_URL
```

when connecting to databases inside Compose.

## Environment Variables

When database services are detected, Dockerez can generate:

```text
.env.example
```

For example:

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=change_me
POSTGRES_DB=app
```

Copy this file to `.env` and provide appropriate values before starting the Compose stack.

```bash
cp .env.example .env
```

On Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Do not commit `.env` files containing real credentials.

## Package Managers

For Node.js projects, dockerez detects common package managers using their lockfiles.

Supported package managers include:

* npm
* Yarn
* pnpm

For example:

```text
package-lock.json → npm
yarn.lock         → Yarn
pnpm-lock.yaml    → pnpm
```

Python projects currently support:

* pip
* Poetry
* Pipenv

## Generated Dockerfiles

Dockerez uses technology-specific templates.

### Vite

Vite applications are built in a Node.js builder stage and served using Nginx.

```text
Node.js
   ↓
npm run build
   ↓
Nginx
   ↓
port 80
```

### Express

Express applications are packaged as Node.js containers and started using the project's production start command.

### Next.js

Next.js applications are built and started using the Next.js production workflow.

### FastAPI

FastAPI applications use a Python container and Uvicorn.

## Development vs Production

Dockerez currently generates **production-oriented Dockerfiles**.

For example, Vite applications are built using:

```bash
npm run build
```

and served by Nginx rather than running the Vite development server.

This means a Compose mapping such as:

```yaml
ports:
  - "5173:80"
```

makes the application available at:

```text
http://localhost:5173
```

while the container itself continues to serve the production build on port `80`.

## Requirements

Dockerez requires:

* Node.js 18 or newer

Docker and Docker Compose are required when you want to build or run the generated containers.

Check your environment with:

```bash
dockerez doctor
```

## Development

Clone the repository and install dependencies:

```bash
npm install
```

During development, Dockerez can be linked globally:

```bash
npm link
```

Then:

```bash
dockerez --help
```

After making changes to the source code, the linked CLI uses the updated files.
